What a new screen has to have

Everything below defaults to Vibe unless a Lofty override is named — see CONTRIBUTING.md. These are the rules a Lofty app screen is measured against once it lists records: the same toolbar, the same four views, the same selection, the same words in the empty state. A screen that answers these differently is a screen somebody has to learn twice.

The rules
  • Four views over one dataset. Board, Table, Gantt, Calendar, one toolbar above all of them. Switching keeps the grouping, the filters, the sort and the search. Leave one out only where it would draw nothing — and say which and why.
  • The filter bar is persistent, inline and one wrapping row. The fields you group by are on it from the start, each reading Any. Everything else is a single Advanced row that opens whole. Never a filter panel, drawer or sidebar — filters must not take the screen the results are on.
  • Advanced carries a count so a filter narrowing the screen from behind a folded row still announces itself, and Clear all clears the grouping with the filters.
  • Every comparable column sorts, and Sort by and Group by reach any property — including one whose column is switched off. Blanks sort last in both directions.
  • Every date is a date picker. Presets — today, yesterday, last 7, last 30, next 30 — plus a custom range. Never two boxes to type into.
  • Columns show, hide and reorder, by drag and by arrow keys, remembered per person.
  • The count line says what is hidden: "Showing 11 of 200", announced as well as drawn.
Selection, drag, and the stand-in
  • A tick box on every row and every card, a select-all, and one bulk bar for the whole selection — a selection made on the board is actionable without switching to the table, and it survives the switch.
  • The bulk bar reassigns and edits: set the person, the team, the status, the stage, a date. Writes go one at a time so a refusal names its record; what was skipped is counted and said before, not discovered after.
  • Selection is page state, never the URL. A link that arrives with eleven records pre-selected is a trap.
  • A lane whose column is a settable value takes a drop. The lane under the card shows a dashed orange edge on --primary-highlighted-color; a lane that will not take it refuses during the drag, so the cursor stays honest, and prints why while there is still time to aim elsewhere.
  • A grouping a drop cannot write says so and names the grouping to switch to. Inert cards with no explanation read as broken.
  • The stand-in is a worked example, not an apology. Say what the screen is for, what to do next, and put the control to do it in the empty state — the create button usually lives in a row that is not being drawn.
  • "Nothing here yet" and "nothing matches" are different sentences, and only the one that actually narrowed offers to clear itself.
